# TrustScore AI**Passive behavioral identity verification — a real-time trust score from 1–100, computed entirely on-device.**\---## What is this?TrustScore AI is a web-based identity verification system that goes beyond traditional KYC checks. Instead of asking "did you enter the right OTP?", it asks a harder question: **are you behaving like the person you claim to be?**During a standard identity flow — entering your name, phone number, Aadhaar, and an OTP — the system silently measures six behavioral and document signals in parallel. These signals are fused into a single trust score between 1 and 100. The entire computation happens in under 10 seconds, with no backend, no external API calls, and no user data leaving the device.\---## The Problem It SolvesIndia's digital financial system processes over 14 billion UPI transactions per month. Yet the identity layer underneath it — phone OTP — is a single point of failure. SIM swap fraud, OTP farming via social engineering, and bot-driven account takeovers all exploit the same gap: **OTP verification proves you received a message, not that you are who you say you are.**Existing solutions fall into two categories:|Approach|Limitation||-|-||OTP only|Proves SIM possession, not identity||Aadhaar e-KYC (UIDAI API)|Requires internet, API credentials, and user consent flow; takes 30–90 seconds||Face liveness detection|Requires camera, ML models, and backend; latency 5–20 seconds||Credit bureau checks|B2B only, not real-time, expensive per-call||Behavioral biometrics (enterprise)|Proprietary, cloud-dependent, $$$, requires long enrollment sessions|TrustScore AI addresses none of these as a replacement — it is a **supplementary passive layer** that adds signal richness to any of the above, with zero infrastructure cost and zero added user friction.\---## How It WorksThe user sees a standard four-screen identity flow:```Enter Name + Phone  →  Enter Aadhaar  →  Enter OTP  →  Score Reveal```Behind the scenes, six signals are collected and scored simultaneously:### Signal 1 — Typing Rhythm Entropy (25 pts)Every keypress generates a timestamp. The system measures:* **Hold duration**: how long each key is pressed down* **Flight time**: the gap between releasing one key and pressing the next* **Coefficient of Variation (CV)** of all flight timesHuman typists show a characteristic rhythm — not perfectly uniform (that's a bot) and not completely chaotic (that's also suspicious). A CV between 0.2 and 1.0 maps to full marks. A CV near zero (machine-generated input) or above 2.0 (random bursts) triggers penalties.Words-per-minute is also computed. A rate above 200 WPM on a form field is physiologically implausible and scored accordingly.### Signal 2 — Tilt / Motion Stability (20 pts)On mobile browsers, the device accelerometer (via the DeviceMotion API) is sampled at 60fps while the user types. Humans hold a phone at a natural angle with small, organic micro-movements. Automated sessions on emulators show zero motion.On desktop browsers, mouse pointer velocity is used as a proxy — the speed and variance of natural hand movement is a weak but non-zero behavioral signal.Both channels are scored using the same metric: the coefficient of variation of movement velocity over the session. Low variance = high score.### Signal 3 — Aadhaar Check-Digit Validation (20 pts)The system implements the **Verhoeff algorithm** — the actual check-digit scheme specified by UIDAI for Aadhaar numbers. This is based on the dihedral group D5 and is significantly more robust than Luhn (used by credit cards).A 12-digit number that:* Does not start with 0 or 1* Passes the Verhoeff check-digit computationscores full marks. A number that fails this check scores zero — it is mathematically invalid regardless of what the user claims. Crucially, this runs entirely locally with no network call.### Signal 4 — OTP Response Time (15 pts)The system records the exact timestamp when the OTP screen appears and when the user submits a correct OTP. The elapsed time is a meaningful fraud signal:|Time window|Interpretation|Score||-|-|-||< 2 seconds|Pre-filled / automated|2/15||2–5 seconds|Very fast but plausible|8/15||5–30 seconds|Natural human SMS-read window|10–15/15||30–60 seconds|Slow but acceptable|7/15||> 60 seconds|Very slow or assisted|5/15|A legitimate user reads an SMS and types six digits in 8–20 seconds. A bot or an OTP-farming call center operator tends to be either suspiciously fast or has characteristic timing patterns.### Signal 5 — SIM Age Heuristic (10 pts)India's mobile numbering plan (MSISDN) assigns number blocks to operators and telecom circles in chronological batches. The 4-digit prefix of a number correlates loosely with when that block was first allocated.The system contains a lookup table of 70+ prefix entries mapping to four age categories:* **Vintage** (pre-2010 blocks, e.g., Airtel Delhi 9810–9811): 10/10* **Mature** (2010–2015, e.g., Airtel 7011): 7/10* **Moderate** (2015–2020, e.g., Jio 6000–7001): 5/10* **Recent** (post-2020 Jio blocks): 2/10An older number suggests an established subscriber, not a freshly SIM-swapped or burner number.### Signal 6 — Phone Format Validity (10 pts)The phone number is validated against India's MSISDN pattern: 10 digits, starting with 6, 7, 8, or 9 (per TRAI allocation). Non-conforming numbers score zero.\---## Scoring and VerdictAll six signals are computed simultaneously and summed:```Total Score = Typing (25) + Motion (20) + Aadhaar (20) + OTP Time (15) + SIM Age (10) + Phone (10)```|Score range|Verdict||-|-||70–100|VERIFIED||45–69|REVIEW||0–44|SUSPICIOUS|The scoring screen reveals each signal progressively with a running total, giving the user (or operator) a transparent breakdown of what passed and what raised flags.\---## What Makes This Novel### 1\. Fully passive — zero added stepsUnlike face liveness, device fingerprinting SDKs, or behavioral biometrics platforms that require enrollment, dedicated sensors, or explicit user consent flows — TrustScore AI collects all signals during interactions the user was already going to perform. There is no "hold your phone still" instruction, no "read the number on screen" challenge, no enrollment session.### 2\. On-device computation, no data egressEvery calculation runs in the browser. No keystroke data, motion samples, Aadhaar digits, or phone numbers are transmitted anywhere. This is a meaningful distinction from cloud-based behavioral biometrics vendors (BioCatch, NeuroID, ThreatMetrix) who ingest raw behavioral streams to proprietary servers.From a regulatory standpoint, this design is compatible with India's Digital Personal Data Protection Act 2023 (DPDP) by construction — there is no personal data processor in the loop.### 3\. Verhoeff algorithm — not a format checkMost implementations that "validate" Aadhaar numbers check the format (12 digits, not starting with 0 or 1) and stop there. TrustScore AI implements the full Verhoeff check-digit computation using the dihedral group D5 multiplication and permutation tables. This catches \~90% of randomly entered fake numbers that would pass a format-only check.### 4\. OTP timing as a fraud signalOTP timing is a well-known signal in academic fraud detection literature but is absent from essentially all production consumer-facing KYC flows. The insight is simple: the distribution of human OTP response times has a characteristic shape. Outliers in either direction (too fast, too slow) carry diagnostic value. This implementation is the first open demonstration of this signal in a complete Indian KYC context.### 5\. MSISDN age as a passive enrichment signalNo public open-source project maps India's MSISDN prefix space to subscriber age categories as a fraud signal. Telecom operators use internal subscriber tenure data for this purpose — it is not publicly accessible. The prefix-table heuristic here is an open approximation of that signal, available without any API.\---## Comparison with the Inspirational Reference (Echo/TrustMatch AI)The [Echo Project](https://github.com/hardik1812/Echo_Project) by Hardik1812 is a Flutter prototype that introduced the concept of behavioral scoring during KYC. The user does nothing differently. The signal is collected as a side effect of normal interaction.**Cost**: Zero marginal cost per verification. No API calls, no cloud compute, no vendor billing.**Accessibility**: Runs on any device with a modern browser. No app install required.**Regulatory fit**: DPDP 2023 and RBI 2024 guidelines emphasize data minimisation and purpose limitation. An on-device system with no data egress is structurally compliant in ways that cloud behavioral biometrics are not.**Layered defense**: TrustScore AI is not designed to replace face liveness or Aadhaar e-KYC — it is designed to sit alongside them as a zero-cost enrichment layer that catches the fraud cases those systems miss (social engineering, SIM swap, OTP farming) while being invisible to the user.\---## Tech Stack|Layer|Choice|Reason||-|-|-||Framework|React 18 + TypeScript|Type-safe, browser-native, no SDK install||Build tool|Vite|Sub-second HMR during development||Styling|Tailwind CSS v4|Utility-first, no design system overhead||Routing|React Router v6|Lightweight SPA navigation||Animations|CSS keyframes|No heavy animation library needed||Sensors|Web DeviceMotion API|Native browser, no package||Backend|None|All computation is local|\---## Project Structure```src/├── models/│   ├── BehavioralSignal.ts     # Operator data on subscriber tenure is not publicly available. The prefix table covers major blocks but is not exhaustive.* **Mouse velocity is a weak tilt proxy** on desktop. The motion signal is most meaningful on mobile browsers with a real accelerometer.* **Verhoeff validation is necessary but not sufficient**. It proves the number is mathematically well-formed; it does not prove it is assigned to the user.* **OTP is mocked** in this demonstration. A production integration would use sandbox.co.in or a licensed SMS gateway.* **Score is advisory**, not deterministic. Behavioral signals are probabilistic. A score of 40 does not prove fraud; a score of 90 does not prove legitimacy. The system is designed to inform human review, not replace it.\---## LicenseMIT — open for use, extension, and contribution.
